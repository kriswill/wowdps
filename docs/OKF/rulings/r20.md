**The call:** A Buff `AuraApplied` / `AuraRefresh` / `AuraRemoved` on a friendly whose spell is in the GENERATED absorb-spell table (`core/src/absorb_spells.rs`: every spell with a `SpellEffect` row whose `EffectAura` is 69, SCHOOL_ABSORB) drives a SHIELD keyed `(raw target, spell id, raw caster)` — aura src = the absorber of `SPELL_ABSORBED`, universally (census: 0 mismatches across ~60 shield spells in both raid logs) — with the parser's trailing `absorb`: APPLIED = the initial size, REFRESH = the NEW RUNNING TOTAL (never a delta), REMOVED = what REMAINED. Transitions: apply `Some(a)` opens `applied = remaining = a` (known), no trailer opens unknown, an apply while open first closes the old shield with `wasted = remaining` when known; refresh `r > remaining` → `applied += r − remaining`, `r < remaining` → `wasted += remaining − r` (a refresh-down overwrites the shield), then `remaining = r`, no trailer = no-op; `Absorbed` on an open key → `consumed += amount`, an over-absorb (`amount > remaining`) raises `applied` by the excess, `remaining = 0`; `Absorbed` on a key not open (the pre-pull shield, a spell outside the table) opens unknown-applied with `consumed = amount` — so an un-generated build never loses healing; removal: `wasted +=` the trailer when present, else `remaining` when the applied size was known, else nothing; a removal trailer off the balance of a KNOWN shield is RAISE-ONLY — above the balance `applied +=` the difference (the over-absorb rule again: stacking shields — Soul Leech, Yu'lon's Grace, Frost Shield — grow with no REFRESH line), below it `applied` is left alone and the shield closes as `unknown` (First In, Last Out shrinks; the row reads visibly inconsistent, never quietly perfect); the shield closes into the row `{applied, consumed, wasted, count, unknown}` where `unknown` counts shields whose APPLIED size was never seen, plus the shrunk ones (the waste is still known whenever a removal trailer exists). A pet's shield keys on its raw guid and folds onto the owner at read like every other ledger, so an aura before its `SPELL_SUMMON` is kept; a `Creature-` guardian's aura before the summon that names its owner is DROPPED (not yet controlled) and its later absorb opens unknown-applied — consistent with taken.txt's pet rule. Segment close folds OPEN shields into their row with `consumed` and `count` only (no applied, no wasted, `unknown += 1`). IDENTITIES, fixture-gated: Σ `rows.consumed` = `absorbed_healing` per player EXACTLY, `applied = consumed + wasted` on every row with `unknown == 0` (raise-only: a fully known row is never short, and a shrink is unknown), no negatives; the healer set (PW:S, Divine Aegis, Chi Cocoon, Life Cocoon, Void Shield) at 0 over-absorbs. `NON_HEALING_ABSORBS` never enter. Auras through the passive gate; absorbs AFTER `record()` (an absorb is combat to the scanner). DERIVED: `absorb_wasted` = Σ wasted over the player's closed shields with a KNOWN waste, `None` when none had one; `shields_unknown` = Σ `unknown`; `absorb_efficiency` = `absorbed / (absorbed + wasted)` when the waste is `Some` and the sum > 0 — never stored (the card writes it for SQL, `null` when unknown, ignored on read). R8, the scanner and segmentation untouched; lazy = full (segment-local, like spans).

**A conflicting change would:** Ledger Feast of Souls or a `Second Wind …,BUFF,0,0` as a shield, read a refresh's running total as a delta and double-count, lose Fel Armor's absorbs from the rows, or report a 0 % efficiency for a shielder whose waste was never observable.

## Detail

THE TABLE: `core/src/absorb_spells.rs` is GENERATED (`tools/gen-absorb-spells.sh` → `tools/extract/src/absorbgen.rs`) from the local install — every spell id with an `EffectAura` 69 `SpellEffect` row, deterministic per build, the R8/R12/R18 generator shape with a sortedness test; the committed fixtures' shields must resolve or the generator fails; a machine without the client ships the committed file, like `role_spells.rs`. The ledger keys on the TABLE, never on the trailer alone, because non-shield buffs carry a nonzero trailer too (Feast of Souls, Soul Fragments, every 15-field `BUFF,0,0`). • PARSER: `absorb: Option<u64>` trails the three aura events — index 13 (`get(f, suffix + 1)`, quote-aware, so a comma in a name never shifts it): `Some(n)` when present and numeric, `Some(0)` on the 15-field `BUFF,0,0` shape (harmless under the table gate), `None` when absent. R18's spans ignore it. • STORE (step 5): the card keeps `absorb_wasted: Option<u64>` (JSON `null` when unknown; a missing key and `null` both read `None`) and `shields_unknown: u32` per player, with `absorb_efficiency` DERIVED on write (`CardPlayer::absorb_efficiency()`, written right after `am_uptime_pct`, `null` when `None`; never read back; a pre-5 card reads `None` / 0); the rows tier keeps `shields[]` — per friendly player with any row `{ guid, rows: [{ spell_id, label, applied, consumed, wasted, count, unknown }] }`, consumed desc; absent on an older file = empty. A night's efficiency (`RoleNight`) is a RATIO OF SUMS over the pulls with a known waste, never a mean of ratios; the DPS / HPS / DTPS measure keeps the Day-bucket mean precedent.
