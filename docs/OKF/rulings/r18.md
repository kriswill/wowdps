**The call:** A Buff `AuraApplied`/`AuraRefresh` on a player whose spell is in the CURATED, generator-validated role table (`ActiveMitigation` / `Defensive` / `External` / `SupportBuff` / `Cooldown`) opens a span keyed by TARGET with the CASTER as `src`; `AuraRemoved` closes the newest; a refresh/removal with no open span opens one at segment start; the close at segment end is read-time and kind-branched; spans capped (`SPAN_CAP`), the `uptime` rollup uncapped; `am_uptime_pct` = the UNION; `externals_given/received` count+ms; `support_uptime` per target. STORE (4b): the card keeps `am_uptime_ms` and the four externals scalars per player with `am_uptime_pct` DERIVED on write (`CardPlayer::am_uptime_pct(duration_ms)` = am_uptime_ms × 100 / duration_ms, 0.0 at duration ≤ 0; never read back; a pre-4b card reads zeros); the rows tier keeps `uptime[]` — the rollup keyed by TARGET, uncapped, `kind` written as the NAME (`MarkKind::name()`, so SQL says `kind = 'external'`; an unknown name drops the cell) — and `coarse[]`: per friendly player the taken and healing series at a fixed 10 s (`taken10` / `heal10`, `bucket_ms` not stored) with ONE merged mark list (item marks + role spans, kinds as codes); the stored Taken drill's `Breakdown.timeline` is the coarse taken series with those marks, and the stored Healing drill serves the details tier's 1 s `heal_timeline` on tier 3 and `heal10` on tier 2; `support_uptime` is never stored (derived from the targets' `support_buff` cells by `src`). R8 untouched, scanner untouched.

**A conflicting change would:** Open a segment from a buff and break scanner/meter lockstep, let a Bloodlust land as a trinket proc, let overlapping mitigation read over 100 %, or lose a fifty-minute key's Shield Block uptime to a capped list.

## Detail

THE TABLE: `core/src/role_spells.rs` is GENERATED (`tools/gen-role-spells.sh` → `tools/extract/src/rolegen.rs`) from a hand-CURATED membership of `(aura id, expected name, kind)` — the `EXTERNAL_BUFFS` precedent grown to five kinds — and the generator VALIDATES every entry against the install: the name must match AND the id must have an APPLY_AURA `SpellEffect` row (a cast id whose buff logs under another id — Metamorphosis 191427 vs its buff 162264 — is a build failure a name check cannot give). Only ids exercised by the committed census of real logs ship (`role_spells.expected.md`: name, kind, observed counts). No class/spec gate — nothing reads one; an external lands on its target regardless of class. • METER: a Buff `AuraApplied` or `AuraRefresh` (`SPELL_AURA_REFRESH`, parsed as `Event::AuraRefresh` — the applied line's 13-field shape — and read ONLY here) on a player whose spell is in the table opens a SPAN keyed by the target with the caster as `src`. Consulted only for auras (`!cast`, never `SPELL_CAST_SUCCESS`), BEFORE the class-spells veto (the table takes `EXTERNAL_BUFFS`' slot — a Warrior's Shield Block is a class spell AND a mitigation span), and BYPASSING the item dedupe rules (own-cast-within-2 s and same-label-within-500 ms are trinket semantics). A re-apply while a span of that spell is open is a REFRESH, not a new span; `AuraRemoved` closes the newest open span of that spell on that target. • SEGMENT-START RULE: a refresh or removal with NO open span opens one at the segment's `start_ms` — the buff predated the segment, the only way a refresh can precede an apply inside it (never on a boss pull, whose byte range starts at the pull; routinely before a trash segment). • PASSIVE GATE: every mark call site — R12 casts and procs INCLUDED — goes through `open_segment_for_passive` (R17's split predicate), so an aura after a segment's end lands nowhere and lazy = full; this also closes R12's stale-segment hole, where a cast after the R4 gap could land on the segment about to be split. Nothing here opens, extends or splits a segment; the scanner is untouched. • READ-TIME CLOSE, kind-branched: a role span still open when the segment ends reads `dur_ms = min(end, now) − at` at read time (a Trash segment has no close event in its byte range, so a mutate-on-close could never be parity-safe); an ITEM mark still open reads 0 (a proc that never dropped is not a span — no R12 golden moves). • CAPS: spans live in their OWN list per target under `SPAN_CAP = 256`, inheriting R12's newest-dropped rule, so a tank's spans cannot evict a trinket proc. `uptime` — per target per `(spell, src)` → `{count, total_ms}` — is an UNCAPPED counter, the fixture-gated measure, so a fifty-minute key's Shield Block uptime is exact after the list wrapped; `am_uptime_ms` is likewise a busy-group counter, never recomputed from the list. • DERIVED (on the segment in 4a-ii, onto the card in 4b): `am_uptime_pct` = the per-millisecond UNION of `ActiveMitigation` intervals on the player — kept uncapped per target and swept at read time, every interval clamped at the segment's close, so a retroactive open (a second mitigation spell first seen by refresh) can never re-count a closed group and the union never exceeds the segment on any kind (externals and support keep their true close: on Trash the passive gate admits an aura up to 60 s past the last hit, so those totals may exceed the R7 clock by that much) — over the segment's `duration_ms` (the same duration the card writes — a key Overall's is the timer), so overlapping buffs never exceed 100 %; `externals_given` = count AND total ms of `External` spans with `src` = the player, `externals_received` likewise by target (a self-cast external is both, so Σ given = Σ received per segment); `support_uptime` per `(target, spell)` for the supporter, from the rollup — the per-spell rollup is the drill behind the union headline. • WIRE (v24): `Segment::timeline()` / `heal_timeline()` marks gain `src` (trailing) and the four new kinds (codes 4–7); the Taken drill's `Breakdown.timeline` is `taken_timeline()`. R8 is unchanged: an aura is never a class signal. Pets fold onto owners at read time like R17's mitigation map.
